## DO-NOT-BREAK Invariants (each cost real debugging)

1. **`-` is ONE anonymous token** shared by the operator rule and the
   negative-number composition. Fusing OPERATOR_GLYPHS into a single
   `token()` forces the LEXER to choose operator-vs-number contextlessly —
   always wrong somewhere. The choice must stay a syntactic GLR fork.
2. **`_nn` family allows positive numbers/vectors** (`til 10`, `f 1 2 3`).
   It exists ONLY to block a *leading negative* in juxt arguments.
3. **Scanner order:** EOS newline check BEFORE comment branch; comment
   branch skips whitespace INCLUDING newlines itself; the continuation
   check must FALL THROUGH to the comment branch (an early `return false`
   ends the scan call and tree-sitter will not re-consult the scanner
   until extras are consumed — orphans comment lines after blank lines).
4. **Scanner cannot know internally-lexed left context.** Never gate a
   token on `prev_was_value`-style state. Whitespace IS observable; use it.
5. **Iterators:** only the `/` family is `token.immediate` (comment rule);
   `'`/`':`/`\`/`\:` may be space-separated (`f[..] ' [..]` is real
   Bloomberg code). `'` reuses `$._quote`.
6. **Vector vs juxt:** LIST_WS scanner branch runs BEFORE NEG_NUMBER;
   `prec.dynamic(2)` on vector beats juxt chains; `1 -1` vector,
   `1 - 1` subtraction.
7. **binary/binary_nn carry `prec.dynamic(1)`** — infix beats the juxt
   reading of `a,'b` / `x f'y`.
8. **Regression gates:** `tree-sitter test` (corpus, 0 failures),
   `python3 scripts/parse_rate.py test/real/` (FLOOR=0.03),
   `python3 scripts/diff_oracle.py --shapes` (23/23).
